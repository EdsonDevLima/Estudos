# Plano de Estudos

## Objetivo

Reaprender, revisar e consolidar uma base forte para trabalhar profissionalmente com:

- C#
- TypeScript
- DDD
- TDD
- Clean Architecture
- Testes unitarios
- Cache
- Mensageria
- SOLID
- AWS
- MVC
- React
- Next.js

O foco deste plano e retomar os fundamentos, revisar o que ja foi estudado, fechar lacunas e transformar revisao em pratica com projetos parecidos com cenarios reais de trabalho.

## Estrategia

Estudar em camadas:

1. Fundamentos de programacao e linguagem
2. Arquitetura e boas praticas
3. Testes e qualidade
4. Desenvolvimento web backend e frontend
5. Escalabilidade e comunicacao entre sistemas
6. Cloud e deploy
7. Projetos completos para consolidacao

Com foco em revisao:

- Revisar primeiro os fundamentos antes de subir o nivel
- Identificar lacunas de conhecimento
- Voltar aos temas importantes em ciclos
- Reescrever exemplos e refazer projetos pequenos
- Consolidar tudo em projetos maiores

## Rotina sugerida

Se voce estudar 2 horas por dia, 5 dias por semana:

- 30 min de leitura e revisao
- 75 min de pratica
- 15 min de anotacoes e resumo do dia

Se puder estudar mais, mantenha a proporcao:

- 30% teoria
- 70% pratica

## Metodo de revisao

Para reaprender com mais consistencia, use este ciclo:

1. Ler o assunto e revisar anotacoes antigas
2. Reescrever um exemplo sem copiar
3. Resolver um exercicio ou criar uma versao pequena
4. Explicar com suas palavras o que entendeu
5. Revisar novamente depois de 24 horas, 7 dias e 30 dias

## Como identificar o que revisar primeiro

Priorize assuntos em que voce:

- lembra o conceito, mas nao consegue implementar
- entende a teoria, mas trava na pratica
- ja estudou antes, mas esqueceu detalhes
- consegue fazer CRUD, mas nao consegue estruturar bem o projeto

- Reaprender a confiar no codigo por meio de testes

- Criar ou retomar o habito de testar antes e durante a implementacao

#### Estudar

- Piramide de testes

- Mocks e stubs

- Pegar codigo ja escrito e adicionar testes depois

## Fase 5 - DDD, Clean Architecture e modelagem

Duracao sugerida: 6 a 8 semanas

#### Objetivos

- Sair da revisao superficial e aprofundar pensamento de dominio
- Reforcar modelagem para negocio real
- Organizar sistemas escalaveis com mais clareza

#### Estudar DDD

- Linguagem ubiqua
- Entidades
- Value Objects
- Aggregates
- Repositories
- Domain Services
- Bounded Contexts
- Eventos de dominio

#### Estudar Clean Architecture

- Camada de dominio
- Camada de aplicacao
- Camada de infraestrutura
- Camada de apresentacao
- Inversao de dependencia
- Casos de uso

#### Relacao com SOLID

- Entender como SOLID ajuda a sustentar DDD e Clean Architecture
- Praticar separacao de responsabilidades
- Evitar classes e servicos inchados

#### Projeto principal da fase

Criar um sistema mais completo, por exemplo:

- E-commerce
- Gestao de pedidos
- Sistema financeiro
- Plataforma de reservas

Esse projeto deve conter:

- API em C#
- Arquitetura em camadas
- Regras de negocio isoladas
- Testes unitarios
- Casos de uso
- Banco de dados
- Frontend em React ou Next.js

#### Revisao ativa da fase

- Revisar um projeto antigo e identificar onde faltou separacao de camadas
- Refazer um modulo usando entidades, casos de uso e regras mais explicitas

## Fase 6 - Cache e mensageria

Duracao sugerida: 4 a 6 semanas

#### Objetivos

- Revisar tecnicas de performance com cache

#### Estudar cache

- Cache aside
- Write through
- Write behind
- Expiracao e invalidacao
- Chaves e estrategia de nomenclatura
- Redis
- Cenarios de cache em APIs e consultas

#### Estudar mensageria

- O que e mensageria
- Filas e topicos
- Publish/subscribe
- Produtores e consumidores
- Retry
- Dead letter queue
- Idempotencia
- Event-driven architecture

#### Projeto da fase

- Sistema de pedidos com cache de leitura e fila para processamento assincrono

#### Revisao ativa da fase

- Comparar implementacao sem cache e com cache
- Revisar diferenca entre processamento sincrono e assincrono

## Cronograma de 30 dias

Este cronograma foi pensado para revisao acelerada. O objetivo em 30 dias nao e dominar tudo em profundidade, e sim:

- reativar memoria tecnica
- revisar os conceitos mais importantes
- praticar com constancia
- fechar lacunas
- terminar com um projeto integrado e revisado

### Regra diaria

Em cada dia, tente seguir esta estrutura:

- 30 min de leitura
- 60 a 90 min de pratica
- 15 min de resumo do que revisou

### Semana 1 - Revisao de base e backend

#### Dia 1

- Revisar C# basico
- Tipos, metodos, classes e interfaces
- Fazer exercicios pequenos sem copiar

#### Dia 2

- Revisar OOP e SOLID
- Reescrever exemplos com SRP, OCP e DIP

#### Dia 3

- Revisar collections, LINQ e async/await

- Criar exemplos assincronos simples

#### Dia 4

- Revisar TypeScript basico
- Types, interfaces, funcoes, generics
- Fazer exercicios pequenos sem framework

#### Dia 5

- Revisar ASP.NET Core basico
- Controllers, services, dependency injection
- Criar uma API simples com CRUD

#### Dia 6

- Revisar MVC e Web API
- Entender diferenca entre responsabilidades
- Melhorar a estrutura da API criada

#### Dia 7

- Revisao geral da semana
- Refatorar o que fez
- Anotar pontos fracos

### Semana 2 - Frontend, testes e integracao

#### Dia 8

- Revisar React basico
- Componentes, props, state e hooks
- Criar componentes pequenos com TypeScript

#### Dia 9

- Revisar formularios, eventos e consumo de API
- Conectar frontend simples com backend

#### Dia 10

- Revisar Next.js
- Rotas, layouts, fetch e componentes server/client
- Subir uma aplicacao simples

#### Dia 11

- Revisar testes unitarios em C#
- xUnit e Moq

#### Dia 12

- Revisar testes em frontend
- Vitest ou Jest
- React Testing Library
- Testar componentes e formularios

#### Dia 13

- Revisar TDD
- Aplicar red, green, refactor em uma regra simples

#### Dia 14

- Revisao geral da semana
- Melhorar testes
- Anotar duvidas e lacunas

### Semana 3 - DDD, Clean Architecture, cache e mensageria

#### Dia 15

- Revisar DDD
- Entidades, value objects e repositories
- Modelar um dominio pequeno

#### Dia 16

- Revisar aggregates, domain services e eventos de dominio
- Melhorar o modelo do dia anterior

#### Dia 17

- Revisar Clean Architecture
- Separar dominio, aplicacao, infraestrutura e apresentacao
- Reorganizar a API nesse formato

#### Dia 18

- Revisar casos de uso e inversao de dependencia
- Refatorar services inchados

#### Dia 19

- Revisar cache
- Cache em memoria, Redis, expiracao e invalidacao
- Adicionar cache em leitura na API

#### Dia 20

- Revisar mensageria
- Filas, publish/subscribe, retry e dead letter queue
- Simular um fluxo assincrono de processamento

#### Dia 21

- Revisao geral da semana
- Comparar arquitetura antiga com a nova
- Documentar os aprendizados

### Semana 4 - AWS e projeto final de consolidacao

#### Dia 22

- Revisar fundamentos de AWS
- IAM, EC2, S3, RDS e CloudWatch

- Revisar SQS, SNS e ElastiCache

#### Dia 26

- Montar frontend do projeto
- Integrar com backend

- Adicionar testes unitarios principais

- Revisar como faria o deploy na AWS
